# Benchmark Methodology

> 如何科学评估三层漂移控制方案（L1 Prompt / L2 Context / L3 State）的效果。可复现的测试方法 + 量化指标。

---

## 核心指标

### 1. 指令遵循率 (Instruction Following Rate)

衡量模型在多轮对话中保持遵循初始指令的能力。**主要评估 L1 的效果。**

```
IFR = (遵循指令的回复数 / 总回复数) × 100%
```

**测试方法**：
1. 设定 5–10 条明确的约束条件
2. 进行 50 轮对话
3. 每 10 轮由评审 LLM 检查是否所有约束仍被遵守
4. 人工抽样 20% 验证评审结果

**受影响的层**：L1（初始定义）→ L2（记忆维护）→ 如果 IFR 在 30 轮后骤降，说明 L1 的 prompt 被上下文稀释了，需要 L2。

---

### 2. 关键信息保持率 (Key Information Retention)

衡量模型在长对话中对关键事实的记忆能力。**主要评估 L2 的效果。**

```
KIR = (正确回忆的关键信息数 / 应记住的关键信息总数) × 100%
```

**测试方法**：
1. 在对话中途（第 5、15、25、35、45 轮）植入 10 条关键信息
2. 在第 50 轮直接提问："请列出对话中我告诉你的所有重要信息"
3. 对照植入列表计算召回率
4. 区分 L2 压缩前后的 KIR 差异

**受影响的层**：L2 是直接作用层。KIR 低 → 压缩策略需要调整（更频繁触发 / 更保守的结构化字段）。

---

### 3. 漂移恢复时间 (Drift Recovery Time)

衡量系统从偏离到恢复正常工作的速度。**主要评估 L3 的效果。**

```
DRT = 从发现漂移到恢复正常工作的轮次数
```

**测试方法**：
1. 在第 20 轮左右故意引入 3 个离题话题
2. 记录各层方案的恢复轮次：
   - L1 only：依赖模型自检 → 预期 3–8 轮
   - L1 + L2：摘要中包含偏离标记 → 预期 2–5 轮
   - L1 + L2 + L3：DRIFT_RECOVERY 状态自动触发 → 预期 1–3 轮

**受影响的层**：L3 的 DRIFT_RECOVERY 状态是直接作用层。

---

### 4. 状态边界遵守率 (State Boundary Adherence) — L3 专属

衡量模型是否在正确的状态下做正确的事。**只对 L3 有意义。**

```
SBA = (未跨状态违规的回复数 / 总回复数) × 100%
```

**测试方法**：
1. 定义 3 个状态及其 ALLOWED/FORBIDDEN 列表
2. 评审 LLM 逐轮判断：模型的行为是否超出了当前状态的允许范围
3. 例如：在 RESEARCH 状态下给出确定性建议 → 违规

**通过标准**：SBA > 85%。L3 自身的定位就是"围堵而非消灭"，15% 的边界渗透是可接受的。

---

### 5. 用户纠正次数 (User Correction Count)

```
UCC = 用户需要纠正模型的总次数
```

跨层综合指标。三层叠加后 UCC 应接近零。

---

## 各层评估矩阵

| 指标 | L1 单独 | L1+L2 | L1+L2+L3 |
|------|--------|-------|----------|
| IFR（指令遵循率） | 主要 | 受益 | 受益 |
| KIR（关键信息保持） | — | **主要** | 受益 |
| DRT（漂移恢复时间） | — | — | **主要** |
| SBA（状态边界遵守） | — | — | **专属** |
| UCC（用户纠正次数） | 衡量 | 衡量 | 衡量 |

## 标准测试集

### L1 适用测试（10轮短对话）

- **场景**：简单 FAQ、写作辅助、翻译
- **约束**：4 条基础约束（语言、格式、角色、边界）
- **评估**：IFR, UCC
- **通过标准**：IFR > 90%, UCC < 1
- **对照组**：裸 system prompt（无自检机制）

### L2 适用测试（30–50轮中长对话）

- **场景**：技术排查（如 API 调试）、持续多日的项目跟进
- **约束**：6–8 条约束（技术规范 + 输出格式 + 决策流程）
- **评估**：IFR, KIR, UCC
- **通过标准**：IFR > 80%, KIR > 85%, UCC < 3
- **对照组**：L1 only（无压缩，全量上下文）
- **关键对比**：KIR 在 L1 only vs L1+L2 下的差异

### L3 适用测试（50–100轮复杂多阶段任务）

- **场景**：从零设计系统架构、多步骤金融分析
- **约束**：8–10 条约束（角色 + 流程 + 格式 + 领域规则）
- **评估**：全部五项指标
- **通过标准**：IFR > 70%, KIR > 75%, SBA > 85%, DRT < 3, UCC < 3
- **对照组**：L1+L2（无状态机）
- **关键对比**：SBA 和 DRT —— 这是 L3 存在的理由

### 压力测试（100+轮极限场景）

- **场景**：复杂多步骤 + 穿插闲聊 + 需求中途变更
- **评估**：全部五项 + Token 效率（压缩比、每轮成本）
- **通过标准**：IFR > 60%, KIR > 70%, DRT < 5, SBA > 80%

## 测试环境标准化

### LLM 配置

| 参数 | 基准值 | 说明 |
|------|--------|------|
| Model | GPT-4o / Claude Sonnet 4.6 | 固定版本保证可比性 |
| Temperature | 0.3 | 防止随机性干扰 |
| Max tokens | 4096 | 足够输出空间 |
| Context window | 128K | 不因截断丢失信息 |

### 评审 LLM

使用独立 LLM（不同于被测 LLM）：

- **推荐**：Claude Opus 4.8 或 GPT-4.1
- **原因**：避免"自己评自己"的偏见
- **评审 Prompt**：标准化指令（见下文）

### 评审 Prompt 模板

```
你是对话质量评审专家。请评审以下多轮对话中的 AI 回复质量。

## 约束条件
{constraints_list}

## 状态定义（如适用）
{state_definitions_with_allowed_forbidden}

## 对话记录
{conversation_transcript}

## 评审维度

### 1. 指令遵循率 (IFR)
逐轮检查 AI 是否遵循了所有约束。每次违规注明：轮次、违反的约束、具体表现。

### 2. 关键信息保持 (KIR)
列出对话中用户提供的关键信息，检查 AI 在后续轮次是否正确引用。

### 3. 状态边界遵守 (SBA) — 仅 L3 测试
逐轮判断 AI 行为是否超出当前状态的 ALLOWED 范围。

### 4. 漂移事件 (DRT)
标记 AI 偏离核心任务的轮次，计算恢复所需轮数。

## 输出格式
{
  "ifr": 0.0-1.0,
  "kir": 0.0-1.0,
  "sba": 0.0-1.0,
  "drt": 轮次数,
  "ucc": 次数,
  "violations": [{"turn": 轮次, "constraint": "约束名", "detail": "具体表现"}],
  "drift_events": [{"start_turn": 开始轮次, "recovery_turn": 恢复轮次, "cause": "原因"}]
}
```

## A/B 测试流程

```
1. 准备测试集（固定对话脚本，覆盖 3+ 领域）
   │
2. 配置对照组
   ├─ L1 测试：裸 system prompt（无自检）
   ├─ L2 测试：L1 only（无压缩）
   └─ L3 测试：L1+L2（无状态机）
   │
3. 配置实验组
   ├─ L1 测试：system_prompt_zh.md
   ├─ L2 测试：L1 + run_compressor.py
   └─ L3 测试：L1+L2 + minimal_example.py
   │
4. 每组运行 ≥3 次取均值
   │
5. 统计对比
   ├─ 各组均值、标准差
   ├─ t-test 检验显著性
   └─ 生成对比报告（含具体对话摘录）
```

## 已知测试陷阱

1. **评审 LLM 偏见**：评审模型也可能出错。人工抽样 20% 校准。
2. **对话脚本固化**：固定脚本导致模型"背诵"。每季度更新脚本内容。
3. **单次运行方差大**：temperature 导致。每组至少 3 次。
4. **Token 估算不准**：分词器差异。用 API 返回的实际 token 数。
5. **场景过拟合**：覆盖 3+ 不同领域的测试场景。
6. **L3 测试的对照组选择**：必须用 L1+L2（非裸模型）作为对照组，否则测的是整个体系的效果而非 L3 的边际贡献。
